# haequiz k6 부하 테스트

골든벨 퀴즈 실서버(https://goldenbellquiz.site)에 **참여자 200명이 동시에 들어와 문제를 푸는 상황**을 k6로 재현합니다.
Windows PC에서 실행하는 기준으로 썼습니다.

## 무엇을 하나

- 참여자 1명 = 웹소켓 1개. 기본 200명이면 **웹소켓 200개**가 열립니다. 운영자의 진행 화면과 관객 화면 연결은 따로 생깁니다.
- 태블릿과 같은 방식으로 붙습니다. SockJS websocket 경로(`/ws/{서버}/{세션}/websocket`)로 연결하고, STOMP를 쓰며, 10초마다 하트비트를 보냅니다.
- **방 만들기와 진행은 운영자가 브라우저에서 직접** 합니다. 스크립트는 PIN만 받고, 비밀번호는 필요 없습니다.
- 참여자 한 명의 동작은 이렇습니다.
  1. 30초에 걸쳐 나눠서 입장합니다.
  2. 문제를 받으면 1~6초 뒤에 보기 하나를 골라 **한 번** 답합니다.
  3. 앞 화면에서 영상이 나오는 동안에는 기다렸다가, 영상이 끝나면(문제 영상은 절반이 지나면) 답합니다.
  4. 결과 발표 15초 뒤에 나갑니다. 운영자가 방 종료를 누르면 그 즉시 나갑니다.
- 참여자 이름은 `1~6학년_1~20반_부하1` ~ `부하200`입니다.

## 1. 준비 (처음 한 번)

PowerShell에서 실행합니다. 한글이 깨지면 **Windows Terminal**에서 PowerShell을 쓰세요.

```powershell
# k6 설치 (winget 이 안 되면 https://dl.k6.io/msi/k6-latest-amd64.msi 를 받아 설치)
winget install k6 --source winget

# 설치 후 새 PowerShell 창을 열고 확인
k6 version

# 이 저장소 받기 (Git 이 없으면: winget install Git.Git)
git clone https://github.com/haequiz/k6.git
cd k6
```

## 2. 방 만들기 (운영자, 브라우저)

1. https://goldenbellquiz.site/login 에서 운영자로 로그인합니다.
2. 진행 화면(`/host`)에서 테스트할 퀴즈를 고르고 **방 만들기**를 누른 뒤 **PIN 6자리**를 확인합니다.
3. **관객 화면 열기**도 눌러 두세요. 실제 행사처럼 0.4초마다 제출 현황을 받는 연결이 하나 더 생기고, 문제 영상의 "절반 지남" 신호도 이 화면이 보냅니다.

## 3. 실행

```powershell
k6 run -e PIN=123456 quiz-load.js
```

처음에는 적은 인원으로 한 번 돌려 보세요. 예: `k6 run -e PIN=123456 -e PLAYERS=20 quiz-load.js`

| 옵션 (`-e 이름=값`) | 기본값 | 뜻 |
|---|---|---|
| `PIN` | (필수) | 방 PIN 6자리 |
| `PLAYERS` | 200 | 참여자 수 = 웹소켓 수 |
| `JOIN_SEC` | 30 | 이 시간(초)에 걸쳐 나눠서 입장 |
| `THINK_MIN_SEC` / `THINK_MAX_SEC` | 1 / 6 | 문제를 받고 답하기까지 걸리는 시간(초) |
| `HOLD_MIN` | 60 | 최대 접속 유지 시간(분). 방이 끝나면 그 전에 끝납니다 |
| `NAME_PREFIX` | 부하 | 이름 앞부분. 같은 방에서 다시 돌릴 때 바꿉니다 |
| `API` | https://api.goldenbellquiz.site | 백엔드 주소 |
| `ORIGIN` | https://goldenbellquiz.site | 웹소켓 Origin 헤더 (서버 허용 목록과 같아야 합니다) |

## 4. 진행 (테스트 중 운영자가 할 일)

1. 진행 화면의 참여자 수가 **200**이 될 때까지 기다립니다. 약 30초 걸립니다.
2. **퀴즈 시작**을 누릅니다.
3. 문제마다 **최소 7~10초**를 기다린 뒤 **답안 마감**을 누르고, 이어서 **다음 문제**를 누릅니다. 참여자는 문제를 받고 1~6초 안에 답합니다.
4. 마지막 문제 다음에는 **결과 발표**를 누릅니다. 15초 뒤 참여자가 모두 나가고 테스트가 끝납니다. **방 종료**를 누르면 바로 끝납니다.

영상이 있는 문제는 관객 화면이 열려 있어야 절반 지점에서 답을 받기 시작합니다. 관객 화면 없이 테스트할 때는 진행 화면에서 **영상 건너뛰기**를 누르세요.

## 5. 결과 보기

테스트가 끝나면 터미널에 요약이 나오고, 같은 폴더에 `result-<PIN>.json`이 저장됩니다.

| 항목 | 뜻 | 기준 |
|---|---|---|
| `ws_sessions` | 열린 웹소켓 수 (200이면 전원 연결) | |
| `hq_connect_ms` | 웹소켓 연결 → STOMP 연결 완료 | |
| `hq_joined` · `hq_join_ms` | 입장 성공 인원 · 입장 응답 시간 | p95 < 1초 |
| `hq_answered` · `hq_answer_ms` | 답 제출 수 · 답 응답 시간 | p95 < 0.5초 |
| `hq_questions_received` · `hq_results_received` · `hq_ended_received` | 문제 · 결과 · 최종 결과를 받은 횟수 | |
| `hq_fail` | 실패 수 (응답 실패 · STOMP 오류 · 연결 오류) | 0 |
| **문항별 도착** | 문제마다 받은 인원과 첫 도착부터 마지막 도착까지 걸린 시간. 서버가 200명 모두에게 보내는 데 걸린 시간입니다 | |

기준을 넘은 항목은 ✗로 표시되고, k6가 오류 코드(99)로 끝납니다. 정상이면 다음처럼 나옵니다.

- `hq_joined` = 200
- `hq_questions_received` = 200 × 문항 수
- `hq_answered` = 200 × 문항 수
- `hq_fail` = 0

## 주의

- **실서버 대상입니다. 행사 중에는 돌리지 마세요.**
- 테스트한 방과 참여자 기록은 운영 DB에 남습니다. 테스트용으로 만든 퀴즈는 출제 화면에서 삭제할 수 있습니다.
- 같은 방에서 다시 돌리면 같은 이름이 "이미 접속 중"으로 막히거나 이전 자리로 이어집니다. 새 방을 만들거나 `-e NAME_PREFIX=부하B`처럼 이름을 바꾸세요.
- 한 방 최대 인원은 500명입니다(서버 설정 `APP_MAX_PLAYERS`).
- 이 테스트는 PC 한 대에서 서버 처리 능력을 봅니다. 학교 와이파이에서 태블릿이 잘 붙는지는 현장에서 태블릿으로 따로 확인해야 합니다.
